# AGENTS.md - leaf-base-redisson

本文用于指导 `leaf-base-redisson` 模块维护。修改本模块时，优先保护 Redisson 连接配置、Spring Cache、可靠主题、延迟队列转发链路和基础工具语义。

## 模块职责

`leaf-base-redisson` 负责：

1. Redisson Client、Spring Cache 和 Redisson MQ 的统一装配。
2. 单机、集群连接配置解析和线程参数配置。
3. 可靠主题发送、订阅、取消订阅和本地监听缓存管理。
4. 延迟队列发送、清理和转发到可靠主题。
5. MQ 监听器在 Spring Bean 生命周期中的注册、注销和资源释放。
6. 分布式锁、计数器、限流、KV、Map Cache 等基础工具能力。
7. 本地配置与 Nacos 配置读取。

本模块不承载业务流程编排、业务域规则或其它 Maven 模块职责。

## 实现原则

1. 不要随意复杂化任何逻辑实现。优先复用 Redisson 原生能力和现有封装；不要引入第二套 MQ、缓存、锁或调度抽象。
2. 遵循单一职责原则。配置装配、MQ 监听、延迟转发、缓存服务和工具方法应保持职责清晰；禁止一个类型包揽连接、监听、转发、重试、缓存和业务处理。
3. 不要随意改变公开 API、配置语义、注解参数、异常语义、订阅规则、延迟队列行为和缓存默认行为。
4. 修改既有逻辑前，先确认旧行为的成功路径、失败路径、空值、边界输入、资源释放和兼容语义。修复缺陷时，必须补回归测试。
5. 变更 MQ 监听注册、注销、转发、重试、回退和销毁清理逻辑前，必须评估重复消费、消息丢失、监听泄漏和资源泄漏风险。
6. 日志、异常消息和断言消息优先使用 ASCII 文本，避免运行环境、终端编码或日志采集链路出现乱码。

## 关键行为

1. `redissonClient`、`redissonMQClient`、`RedissonSpringCacheManager` 的装配语义不得随意改变。
2. 单机/集群判断、地址解码、线程参数默认值和鉴权字段必须保持兼容。
3. 可靠主题订阅键生成规则和幂等注册行为不得破坏。
4. 延迟队列转发失败后的重试、回退和清理策略必须保持可观测。
5. 缓存 TTL、批量写入、刷新、删除和空参数处理必须语义明确。
6. 分布式锁、计数器、限流等工具方法必须明确释放、超时和异常封装语义。

## 测试要求

1. 需要完整的单元测试。涉及行为变更时，测试必须覆盖成功、失败、异常、空值、边界和回归场景。
2. 涉及线程并发、资源释放、重试、缓存刷新、订阅去重、延迟队列转发、监听注册/注销、连接配置解析等关键功能点时，必须补充冒烟测试或集成测试。
3. 涉及性能关键节点时，至少要有可执行的冒烟验证，覆盖重复执行、批量输入、空输入和异常输入；无法自动化时，在交付说明中写清手工验证命令、样本规模和观察指标。
4. 依赖 Spring Boot 自动配置、BeanPostProcessor、Redisson Bean 装配、监听注册、线程池生命周期或销毁清理的功能，必须使用接近真实运行形态的 Spring Boot 测试。
5. 重点覆盖 `GXRedissonSpringDataConfig`、`GXRedissonMQConfig`、`GXRedissonMQUtils`、`GXRedissonDelayMQPostProcessor`、`GXRedissonCacheServiceImpl` 和 `GXRedissonUtils` 的核心路径。

## 变更检查

提交或交付前确认：

1. 是否只修改了 `leaf-base-redisson` 模块；确需跨模块时，先说明原因和最小影响范围。
2. 是否影响连接配置、Spring Cache、可靠主题、延迟队列、监听器注册或基础工具语义。
3. 是否评估了性能、资源释放、并发可见性和线程安全风险。
4. 是否引入了不必要的复杂分支、抽象层、缓存、反射或跨职责类型。
5. 是否补充并运行了与风险相匹配的单元测试、冒烟测试或集成测试。

## 推荐命令

```powershell
mvn -pl leaf-base-redisson -am test
```

# AGENTS.md - leaf-base-framework

本文用于指导 `leaf-base-framework` 模块维护。该模块是 Maple Leaf Framework 的基础核心，修改时必须优先保持公共契约、默认行为和跨模块兼容性稳定。

## 模块职责

`leaf-base-framework` 负责：

1. 通用注解、AOP、Web 横切、过滤器、拦截器和统一异常处理。
2. 基础 DTO、统一返回结构、异常模型、校验、转换和通用工具。
3. 缓存配置、事件机制、MDC/TraceId、上下文传播和并发工具。
4. DDD 基础接口、文件上传、动态方法调用和框架公共支撑能力。

本模块不承载具体业务域规则、业务流程编排、业务常量或业务协议适配。

## 实现原则

1. 不要随意复杂化任何逻辑实现。优先复用 Spring Boot、Spring Framework、JDK 和本模块既有工具；不要重复造框架原生能力。
2. 遵循单一职责原则。禁止一个类型同时包揽 Web、缓存、并发、反射、转换、事件、上下文传播等多类职责；公共工具也必须保持边界清晰。
3. 不要随意改变公开注解、DTO 字段、公共方法签名、默认行为、异常语义、序列化协议和配置键。
4. 修改既有逻辑前，先确认旧行为的成功路径、失败路径、空值、边界输入和兼容语义。修复缺陷时，必须补回归测试。
5. 只有逻辑确实被两个以上位置复用，或能明显降低重复复杂度时，才抽取新方法或新类。
6. 日志、异常消息和断言消息优先使用 ASCII 文本，避免运行环境、终端编码或日志采集链路出现乱码。

## 关键行为

1. 涉及公共 DTO、返回结构、异常模型、注解和工具 API 的改动，默认视为跨模块兼容性变更。
2. 涉及 `ThreadLocal`、MDC、TraceId、异步执行和事件分发时，必须有清理、恢复和异常传播路径。
3. 公共并发工具必须明确超时、取消、中断恢复、空集合、集合内空元素和异常聚合语义。
4. SpEL 表达式缓存 key 应保持稳定，不要把用户实参直接拼进表达式文本。
5. 配置类应保持可读、可覆盖、可观测，避免硬编码环境值。
6. 禁止提交真实密钥、令牌、生产地址或密码。

## 测试要求

1. 需要完整的单元测试。涉及行为变更时，测试必须覆盖成功、失败、异常、空值、边界和回归场景。
2. 涉及线程并发、`ThreadLocal`、MDC/TraceId、缓存、事件、AOP、反射、转换、SpEL、Web advice/filter/interceptor 等关键功能点时，必须补充冒烟测试或集成测试。
3. 涉及性能关键节点时，至少要有可执行的冒烟验证，覆盖重复执行、批量输入、空输入和异常输入；无法自动化时，在交付说明中写清手工验证命令、样本规模和观察指标。
4. 依赖 Spring Boot 容器、自动配置、AOP、Web、异步或事件机制的功能，必须使用接近真实运行形态的 Spring Boot 测试。
5. 修改公共 DTO 或协议对象时，至少验证序列化、反序列化或核心字段兼容性。

## 变更检查

提交或交付前确认：

1. 是否只修改了 `leaf-base-framework` 模块；确需跨模块时，先说明原因和最小影响范围。
2. 是否影响公开注解、DTO、异常、Web advice/filter/interceptor、缓存、事件、MDC 或并发工具语义。
3. 是否引入了不必要的复杂分支、抽象层、缓存、反射或跨职责类型。
4. 是否评估了性能、线程安全、资源释放和上下文清理。
5. 是否补充并运行了与风险相匹配的单元测试、冒烟测试或集成测试。

## 推荐命令

```powershell
mvn -pl leaf-base-framework test
```

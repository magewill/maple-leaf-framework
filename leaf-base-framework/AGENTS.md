# AGENTS.md (leaf-base-framework)

## 模块定位

`leaf-base-framework` 是 Maple Leaf Framework 的基础核心模块，提供跨业务复用的框架能力，包括通用注解、AOP、Web 横切、基础 DTO、统一返回结构、异常模型、缓存配置、事件、上下文透传、MDC、通用工具和 DDD 基础接口。

本模块不得引入具体业务域规则、业务流程编排或业务常量。

## 模块边界

- 每次修改只能修改当前 Maven 模块；除非用户明确要求或跨模块编译契约必须同步调整，不得修改其它模块代码、配置或测试。
- 对外注解、DTO 字段、公共方法签名、默认行为、异常语义和序列化协议默认视为稳定契约。
- 现有代码已经在生产环境使用，不得随意更改对外接口规范；确需调整时必须评估兼容性，并补充迁移说明和回归测试。
- 完善已有功能时，必须以确保原有功能正确性为前提；修改既有逻辑时，不得破坏现有正确行为，修复范围应尽量收敛。

## 开发约束

- 本模块作为基础框架，性能、线程安全性和资源释放路径都是核心质量要求；公共工具、缓存、上下文透传、反射和转换逻辑修改时必须重点审查热点路径开销与并发安全。
- 在线程池与虚拟线程都能满足需求的场景中，优先使用虚拟线程；只有需要固定线程资源、复用线程本地状态、绑定专用调度器或受第三方组件限制时，才优先选择传统线程池。
- 新增能力优先复用 Spring Boot / Spring Framework 标准机制；新增前必须先判断是否与框架原生能力重复，若重复，优先使用原生能力或基于扩展点增强。
- 不要随意把已存在代码抽取成单独方法或类；只有抽取后的逻辑至少能被两个以上位置复用，或能显著降低复杂度时，才进行抽取。
- 所有 `log` 日志内容必须使用 ASCII 字符，避免不同运行环境、终端编码或日志采集链路出现乱码。
- 配置类保持可读、可覆盖、可观测，避免硬编码环境值。
- 涉及请求上下文的逻辑必须考虑异步线程和非 Web 调用。
- 涉及 ThreadLocal / MDC 的代码必须有清理路径。
- 禁止提交真实密钥、令牌、生产地址或密码。

## 测试要求

- 严格遵循测试驱动最佳实践：先用测试明确问题或目标行为，再进行最小实现，最后通过回归测试确认既有正确行为没有被破坏。
- 涉及代码改动时，必须同步查看相关测试用例是否完整覆盖改动点；若覆盖不足，应补充或更新测试。
- 测试用例必须覆盖成功、异常、空值、边界和回归场景。
- 如果功能依赖 Spring Boot 应用启动后的容器、自动配置、AOP、Web、异步或事件机制，测试应使用接近真实的 Spring Boot 应用上下文启动方式验证。
- 修改 `aspect`、`web.advice`、`filter`、`handler`、`wrapper.mdc` 时，必须重点检查成功路径、异常路径、空值路径和框架扩展点行为。
- 修改公共 DTO 或协议对象时，至少验证序列化、反序列化或核心字段兼容性。
- 最小验证命令：`mvn -pl leaf-base-framework test`。

## 并发与线程工具约束

- 新增或修改线程池、`CompletableFuture`、异步事件、MDC/TraceId 透传逻辑时，必须覆盖正常完成、异常完成、超时、取消和中断恢复路径。
- 在线程池线程中写入 MDC 或 ThreadLocal 后，必须在 `finally` 中恢复调用前上下文；没有上游上下文时必须显式 `clear`，避免复用线程携带脏数据。
- `CompletableFuture.cancel(true)` 默认不保证中断底层任务；如果 API 语义要求取消运行中的任务，需要将取消动作传递到实际提交给 `ExecutorService` 的 `Future`。
- 不要向 `ConcurrentHashMap`、`ConcurrentMap` 默认实现写入 `null` 值；聚合结果需要区分失败、空结果和缺失时，应使用显式哨兵值或专门结果对象。
- 等待多个异步任务时，超时或异常后要记录已完成/未完成数量，并对未完成任务执行取消；捕获 `InterruptedException` 后必须恢复线程中断标记。
- 接收 `Future` / `CompletableFuture` 集合的公共方法必须显式拒绝 `null` 集合、空集合和集合内的 `null` 元素，避免在等待阶段暴露不清晰的 NPE。
- 模块级共享线程池属于 JVM 生命周期资源；除 JVM 关闭流程或专门生命周期测试外，不要在普通单元测试、请求流程或业务流程中调用关闭方法。
- 并发工具测试需要避免依赖全局统计初始值；可验证统计格式、状态变化方向或任务结果，不要假定测试 JVM 中没有其他任务运行。

## SpEL 工具约束

- SpEL 表达式缓存的 key 应尽量保持稳定，不要把用户实参直接拼进表达式文本；方法实参优先通过 `EvaluationContext` 变量绑定。
- 拼装 SpEL 方法调用时必须避免字符串转义、同类型参数变量名冲突和对象参数泄漏；变量名应使用调用内稳定的索引形式，例如 `#p0`、`#p1`。
- 公共方法调用工具必须支持无参方法；`null` 参数类型数组按空数组处理，`null` 实参数组按空实参数组处理。
- 修改表达式缓存、方法缓存或上下文构造器时，必须考虑并发调用、缓存上限、异常路径以及 Spring `StandardEvaluationContext` 非共享使用原则。

## 文档与注释

- 删除方法、类、变量上的冗余注释；能够通过命名、类型和局部代码直接理解的内容，不再添加或保留重复解释。
- 对复杂的方法、类、扩展点或公共工具能力，适当补充必要的 Javadoc；只保留语义说明、边界条件、异常约定等必要信息。
- 清理 Javadoc 中重复、空泛或仅复述方法签名的信息；如果使用方式比较复杂，可以补充简短使用示例，便于使用者参考。

## AGENTS.md 更新时机

以下场景必须主动检查并更新 `AGENTS.md`：

- 删除、替换或新增模块级框架能力时。
- 发现已有规则与 Spring Boot / Spring Framework 原生机制重复或冲突时。
- 调整模块边界、目录职责、公共扩展点或稳定契约时。
- 修复的问题暴露出可复用的开发约束、红线或测试要求时。
- 引入新的基础设施依赖、跨模块约定或默认开发流程时。

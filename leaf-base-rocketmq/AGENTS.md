# AGENTS.md - leaf-base-rocketmq

本文用于指导 `leaf-base-rocketmq` 模块维护。修改本模块时，优先保持 RocketMQ 配置装配、消息发送语义和对外发送契约稳定。

## 模块职责

`leaf-base-rocketmq` 负责：

1. `rocketmq` 配置读取与装配，支持本地 YAML 和 Nacos 配置来源。
2. RocketMQ 消息发送请求模型，包括 topic、tag、body、delay、messageKey。
3. 基于 `RocketMQTemplate` 的普通发送、同步发送、异步发送、单向发送和延迟发送。
4. 发送前参数校验、发送结果判定和框架异常封装。
5. 轻量 CDC 消费适配，将原始消息转换为统一事件并分发给本地监听器。

本模块不承载通用消费容器、事务消息编排、复杂重试补偿、业务幂等或跨服务路由编排。

## 实现原则

1. 不要随意复杂化任何逻辑实现。优先复用 `RocketMQTemplate` 和现有发送契约；不要并行引入另一套发送抽象、路由框架或补偿机制。
2. 遵循单一职责原则。发送服务、配置加载、请求模型、CDC 解析和本地分发应保持职责清晰；禁止一个类型包揽发送、配置、重试、监听和业务处理。
3. 不要随意改变 `GXSendRocketMQService` 现有方法语义、返回值、异常语义、参数约束、配置键和默认值。
4. 修改既有逻辑前，先确认旧行为的成功路径、失败路径、空值、边界输入和兼容语义。修复缺陷时，必须补回归测试。
5. CDC 能力只负责原始消息解析、开关判断、事件规范化和本地监听器分发；业务幂等、落库事务、跨库路由和重试补偿应由业务模块或专门同步模块负责。
6. 日志、异常消息和断言消息优先使用 ASCII 文本，避免运行环境、终端编码或日志采集链路出现乱码。

## 关键行为

1. 消息目的地拼装必须保持 `topic`、空 `tag`、`topic:tag` 约定稳定。
2. `messageKey`、`body`、`deliverTime` 的处理会影响上游调用方和 RocketMQ 控制台排障方式，不能随意改变。
3. 配置来源通过 `rocketmq.config-source` 显式选择；默认值和本地/Nacos 切换语义不得随意改变。
4. 异步发送回调必须明确处理成功、非 `SEND_OK`、空结果和异常分支。
5. CDC 无效消息、未知 op、关闭开关、监听器过滤等分支必须保持可观测。

## 测试要求

1. 需要完整的单元测试。涉及行为变更时，测试必须覆盖成功、失败、异常、空值、边界和回归场景。
2. 涉及线程并发、异步回调、共享状态、批量发送、CDC 分发、配置绑定、条件装配、发送结果判定等关键功能点时，必须补充冒烟测试或集成测试。
3. 涉及性能关键节点时，至少要有可执行的冒烟验证，覆盖重复执行、批量输入、空输入和异常输入；无法自动化时，在交付说明中写清手工验证命令、样本规模和观察指标。
4. 涉及配置来源、条件装配或启动期行为时，不能只写纯单测，必须至少补一个 Spring Boot 上下文启动测试验证真实装配结果。
5. 重点覆盖 `GXSendRocketMQServiceImpl` 参数校验、目的地拼装、发送结果判定、异常封装、延迟时间换算、异步回调、CDC 消息解析和监听器分发。

## 变更检查

提交或交付前确认：

1. 是否只修改了 `leaf-base-rocketmq` 模块；确需跨模块时，先说明原因和最小影响范围。
2. 是否影响 `GXSendRocketMQService` 对外契约、消息目的地拼装、messageKey、延迟发送或异常语义。
3. 是否影响配置来源切换、本地/Nacos 条件装配或启动期行为。
4. 是否引入了不必要的复杂分支、抽象层、缓存、反射或跨职责类型。
5. 是否补充并运行了与风险相匹配的单元测试、冒烟测试或集成测试。

## 推荐命令

```powershell
mvn -pl leaf-base-rocketmq -am test
```

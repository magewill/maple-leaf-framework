# AGENTS.md - leaf-base-retry

本文档用于指导 `leaf-base-retry` 模块后续迭代开发。修改本模块时，优先保证重试语义稳定、失败恢复可预期、日志可观测，并避免无关重构。

## 1. 模块定位

`leaf-base-retry` 是 Maple Leaf Framework 的通用重试基础模块，主要提供：

1. 基于 Spring Framework Retry API 的统一重试配置（`GXRetryConfig`）。
2. 可编程重试工具（`GXRetryUtil`），支持同步、异步、恢复回调、自定义异常重试策略。
3. 重试生命周期监听（`GXRetryListener`），用于记录重试开始、失败、成功、耗尽、中断、超时等事件。
4. 回调与上下文抽象（`GXRetryCallback`、`GXRecoveryCallback`、`GXRetryContext`）。

不在本模块内承载具体业务流程、业务补偿编排或业务域异常语义。

## 2. 目录职责

1. `config`：重试模板和重试策略构建逻辑。
2. `util`：对外主入口工具，封装多种重试调用方式。
3. `listener`：重试过程观测与日志行为。
4. `callback`：重试执行回调、恢复回调接口契约。
5. `context`：重试上下文对象与属性传递能力。

## 3. 强制开发规则

1. 所有 `log` 日志内容必须使用 ASCII 字符，禁止新增或保留非 ASCII 日志文案。
2. 涉及改动的点，必须同步检查测试用例是否完整覆盖；覆盖不足时必须补充测试。
3. 不要随意把已存在代码抽取成单独方法或类；仅当抽取后可被两个及以上位置复用，或显著降低复杂度时才允许抽取。
4. 删除方法、类、变量上的冗余注释，避免注释重复描述代码字面含义。
5. 在复杂方法、复杂类、对外扩展点上，适当补充 Javadoc，并在必要时加入简短使用示例。
6. 变更重试默认参数（次数、间隔、倍率、最大间隔）前，必须评估兼容性与调用侧影响。
7. 变更异常重试映射（include/exclude）前，必须评估是否会导致“应快速失败却被重试”或“应重试却提前失败”。

## 4. 测试要求

1. 任何功能改动必须覆盖成功路径、失败路径、异常路径、边界条件。
2. `GXRetryUtil` 相关改动至少覆盖：
   - 默认重试参数行为。
   - 自定义重试参数生效。
   - 指定异常可重试/不可重试。
   - 恢复回调触发条件与上下文内容。
   - 异步重试封装异常行为。
3. `GXRetryConfig` 相关改动至少覆盖：
   - 参数校验上下界。
   - `RetryPolicy` include/exclude 生成逻辑。
   - 默认重试异常映射回归检查。
4. `GXRetryListener` 相关改动至少覆盖：
   - 不同重试阶段回调触发。
   - cache 清理逻辑与边界。
   - 不同日志级别下分支行为。
5. 如果功能依赖 Spring 容器、自动配置、AOP 代理或 Bean 装配，测试必须使用接近真实运行形态的 Spring Boot 启动测试（如 `@SpringBootTest`），不能只做纯单元测试。
6. 至少保证模块级测试命令可执行：`mvn -pl leaf-base-retry test`。

## 5. 变更前检查清单

1. 是否影响 `GXRetryUtil` 对外重载方法语义或异常传播语义。
2. 是否影响 `GXRetryContext` 的 `retryCount`、`lastThrowable` 和属性读取行为。
3. 是否影响 `GXRetryConfig` 的默认值、参数校验或异常映射。
4. 是否引入了非 ASCII 日志内容。
5. 是否出现了不必要的方法/类抽取。
6. 是否移除了冗余注释并补齐必要 Javadoc/示例。
7. 是否已补充并运行与改动点匹配的测试。

## 6. AGENTS.md 自动触发更新时机

出现以下任一情况时，必须在同一 PR/提交中同步更新本文件：

1. 模块职责边界变化（新增或移除核心能力）。
2. 目录结构变化（新增关键包、迁移核心类、删除关键组件）。
3. 对外契约变化（`GXRetryUtil` 公共方法签名、回调接口语义、上下文字段语义）。
4. 默认重试策略变化（次数、间隔、倍率、最大间隔、默认异常映射）。
5. 监听与日志策略变化（日志级别策略、缓存策略、可观测字段）。
6. 测试基线变化（新增必须集成测试形态，或模块最低测试门槛变化）。
7. 团队新增长期执行的开发约束（编码、测试、文档、兼容性规则）。

## 7. 提交说明建议

1. 涉及重试策略变更时，PR 描述必须说明行为变化、兼容性影响和回滚方式。
2. 涉及异常映射变更时，PR 描述必须明确“哪些异常会重试、哪些不会重试”。
3. 提交前确认新增/修改日志均为 ASCII。
4. 提交前确认测试已覆盖改动点，并在 PR 中说明关键验证结果。

# 契约：审查报告结构与校验规则

**适用范围**: `specs/004-redisson-module-audit/review-report.md`
**约束来源**: spec FR-002/FR-003/FR-009/FR-010、data-model.md §1/§2

本契约规定审查报告的**文件结构、条目格式与机器可校验规则**。报告是实现阶段（`/speckit.implement`）的交付物，本阶段只固定其形状。

## 1. 文件结构（顺序固定，不得增删章节）

```text
# leaf-base-redisson 审查报告
## 1. 结论摘要                # 与 spec.md 的三维结论表一字不差
## 2. 审查范围与基线          # 文件数、测试基线、依赖版本、证据等级说明
## 3. 发现清单                # F-01…F-16，按 fixBatch 分组
## 4. 链路可靠性矩阵          # 5 条链路，唯一定性
## 5. 并发与生命周期矩阵      # 组件 × 并发度 × 停止路径 × 泄漏
## 6. 性能口径                # 3 条路径 + 锁工具的往返计数与复算方式
## 7. 契约对照表              # AGENTS.md / 方法签名 / 配置键 vs 实现
## 8. 未验证假设              # 无 S/D/T 支撑的条目（可为空，但章节必须存在）
## 9. 证据附录                # E-01…E-13
## 10. 复现索引               # 每条 F 的复现入口（命令或用例名）
```

## 2. Finding 条目格式（逐条照抄模板，字段顺序不变）

```markdown
### F-NN [级别] 标题

- **维度**: 逻辑正确性 | 线程安全 | 性能
- **证据等级**: S | D | T
- **位置**: `path/to/File.java:120-136`
- **触发条件**: ...
- **影响**: ...
- **证据**: E-NN（+ 一句可核对摘录）
- **复现**: `命令` 或 `用例全名` → 预期现象
- **回归测试设计**: 输入 ... ; 断言 ... ; 修复后应翻转为 ...
- **修复批次**: P0 | P1 | P2 | 仅文档
- **契约影响**: none 或具体说明
```

## 3. 机器可校验规则（交付前逐条执行）

| 编号 | 规则 | 校验方式 |
| --- | --- | --- |
| C-01 | 每条 Finding 必含上述 10 个字段，缺一即不合格 | 按 `- \*\*字段\*\*:` 计数，每条应为 10 |
| C-02 | `F-NN` 编号唯一且与 `spec.md` 的发现清单完全一致（数量与编号） | 比对两侧编号集合 |
| C-03 | `E-NN` 编号与 `spec.md` 证据列表一致；报告可追加 `E-NN+`，不得改写已有序号语义 | 比对两侧编号集合 |
| C-04 | 级别 ∈ {高,中,低}，维度 ∈ {逻辑正确性,线程安全,性能}，批次 ∈ {P0,P1,P2,仅文档} | 枚举检查 |
| C-05 | 级别 = 高 的条目，`复现` 与 `回归测试设计` 均非空，且证据等级 ∈ {D,T} | 字段非空检查 |
| C-06 | 每条 Finding 至少引用 1 个 `E-NN` | 正则 `E-\d{2}` |
| C-07 | 第 1 章结论摘要与 `spec.md` 的"审查结论"表逐字一致 | 文本比对 |
| C-08 | 第 4 章 5 条链路均有定性，取值为 {至少一次,至多一次,尽力投递} | 枚举检查 |
| C-09 | 第 6 章每个路径的往返次数为整数，无"约/大概/左右" | 正则 `约\|大概\|左右` 计数为 0 |
| C-10 | 第 8 章存在；若为空必须写 `（无）`，不得删除章节 | 章节标题存在性检查 |

## 4. 与 spec 的一致性契约

- 报告是 `spec.md` 摘要的展开，两者冲突时**以 `spec.md` 的需求为准**，报告必须修订（FR-009）。
- 报告不得新增未在 `spec.md` 中登记的高危结论；若审查中发现新的高危项，先更新 `spec.md` 的发现清单，再写入报告。
- 报告不得把 `f-15` 类"既定契约"计入缺陷总数；摘要中的缺陷计数必须与第 3 章 `级别=高|中` 且 `批次≠仅文档` 的条目数一致。

## 5. 反例（明确禁止）

- 只写"存在并发问题，建议加锁"而不给位置与触发条件。
- 用"理论上""可能"描述已确认的缺陷，或用"必然"描述未验证的假设。
- 把修复补丁贴进报告正文（修复属后续规格，报告只给建议与影响）。
- 复制上游 Redisson 源码超过 2 行（用"类名#方法名 + 语义摘要"替代）。

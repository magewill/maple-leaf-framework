# CR-20261126-057：GXCGLibDataConvert 的 BeanCopier 缓存改为 ClassValue，修复与 F-16 同根因的缓存失效

- 类型：`bugfix`
- 状态：`applied`
- 影响：无 `spec.md` / `plan.md` / `tasks.md` 需求变更；`convert/GXCGLibDataConvert.java`、`converter/GXCGLibDataConvertTest.java`
- 日期：2026-11-26
- 关联命令：`manual`（CR-20261126-056 评审遗留项）
- 原始记录位置：`specs/005-framework/spec.md` F-16 / E-17（同类缺陷的未登记实例）

## 背景 / 现象

`GXCGLibDataConvert` 内有三个弱键缓存，评审时逐个核对键的存活条件：

| 缓存 | 键 | 判定 |
| --- | --- | --- |
| `CONVERTER_CACHE` | `Class<?>` | 键本身正确，但**值会反向强引用键**（值 → `ClassMetadata` → `Field` → `declaringClass`），弱键实际永不生效。本 CR 未察觉，由 CR-20261126-058 改正 |
| `CLASS_METADATA_CACHE` | `Class<?>` | 同上，同样由 CR-20261126-058 改正 |
| `BEAN_COPIER_CACHE` | `new BeanCopierCacheKey(sourceClass, targetClass)` | **失效**——键是每次调用新建的记录对象，外部不保留强引用 |

`BEAN_COPIER_CACHE` 与 CR-20261126-053 修掉的 F-16 完全同根因：`computeIfAbsent` 返回后键即不可达。注意命中率的准确描述——Hutool 的 `WeakObj.equals` 按 referent 比较，所以**GC 之前是能命中的**；缺陷在于 `ReferenceConcurrentMap` 每次操作都先 `purgeStale()`，键一旦不可达，下一次 GC 就会清掉条目。于是缓存寿命由 GC 频率决定，反复执行 `BeanCopier.create`（生成字节码）持续推高 metaspace。该文件此前未被 F-16 的审计登记。

## 变更前

```java
private static final Map<BeanCopierCacheKey, BeanCopier> BEAN_COPIER_CACHE =
        new WeakKeyConcurrentMap<>(new ConcurrentHashMap<>(2048));

private static BeanCopier getBeanCopier(Class<?> sourceClass, Class<?> targetClass) {
    return BEAN_COPIER_CACHE.computeIfAbsent(new BeanCopierCacheKey(sourceClass, targetClass),
            k -> BeanCopier.create(sourceClass, targetClass, true));
}

private record BeanCopierCacheKey(Class<?> sourceClass, Class<?> targetClass) { }
```

## 变更后

```java
private static final ClassValue<ConcurrentMap<Class<?>, BeanCopier>> BEAN_COPIER_CACHE = new ClassValue<>() {
    @Override
    protected ConcurrentMap<Class<?>, BeanCopier> computeValue(Class<?> type) {
        return new ConcurrentHashMap<>(8);
    }
};

private static BeanCopier getBeanCopier(Class<?> sourceClass, Class<?> targetClass) {
    return BEAN_COPIER_CACHE.get(sourceClass).computeIfAbsent(targetClass,
            key -> BeanCopier.create(sourceClass, key, true));
}
```

- 以**源类型**作 `ClassValue` 槽位，槽内以**目标类型**（`Class` 强引用）为键。本类的 copier 恒为 `useConverter = true`，无需在键里带该标志。
- 同一类型对只生成一次字节码；条目随源类型卸载释放，类加载器不会被钉住。
- 删除 `BeanCopierCacheKey` record 与对应的 `WeakKeyConcurrentMap` 声明。当时另外两个 `Class` 键缓存仍在使用 `WeakKeyConcurrentMap`，故保留了导入；CR-20261126-058 把它们一并改为 `ClassValue` 后，该导入已删除。
- 未改为复用 `util/cglib/GXBeanCopierCache`：那会让 `convert` 与 `util.cglib` 形成双向包依赖（`GXCglibUtils` 已依赖 `GXCGLibDataConvert`），与 `leaf-base-framework/AGENTS.md` 第 19 条"公共工具必须保持边界清晰"冲突。

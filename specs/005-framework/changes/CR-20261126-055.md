- 日期：2026-11-26

- 原始记录位置：`specs/005-framework/spec.md` E-21 / F-16；`coverage-ledger.md` 第 258 行

## 背景 / 现象

对 `GXCommonUtils` 做逐方法评审，确认 3 处会真实出错的缺陷与若干静默降级；其中反射缓存整体清空、`buildTree` O(n²) 是 CR-20261126-053 明确留待处理的 F-16 剩余项。

## 变更前

1. `convertSourceToTarget`（`catch (Exception e)`）把 `verify()` / `customizeProcess()` 抛出的 `GXBeanValidateException`、`GXBusinessException` 一并包装成 `GXConvertException`。`GXExceptionHandler` 对两者的响应不同：前者返回业务码与字段明细，后者只返回 `500 数据转换错误!`。
2. `reflectCallObjectMethod` 用 `method.canAccess(object)` 判断可访问性；对**静态方法**传非 null 对象会抛 `IllegalArgumentException: non-null object for public static ...`，被误报为"Reflection argument mismatch"。
3. `reflectCallObjectMethod` 不支持可变参数方法（`getParameterCount()` 与实际实参个数不等，永不匹配，静默返回 `null`），也不支持基本类型拓宽（`Integer` 实参匹配不上 `long` 形参）。
4. `convertStrToTarget` 解析 `{k=v}` 形态时用 `str.replace("{","").replace("}","")` 删除**所有**花括号再 `split(",")`，导致嵌套值与含逗号的值被破坏（`{data={"x":1}}` → `data="x":1`）。
5. `METHOD_CACHE` 为静态 `ConcurrentHashMap`，键含 `Class` 强引用，超 4096 时整体 `clear`（抖动 + 类加载器钉住）；`buildTree` 每个父节点全量过滤 `subs` 并逐元素反射，O(n²) 且重复 id 会无限递归。
6. 两个 `getEnvironmentValue` 重载约 50 行重复，且失败语义不一致（无默认值版本遇 `JacksonException` 抛异常，带默认值版本吞掉）。
7. `checkHmac` 与 `generateHmac` 的 HMAC 计算重复；`convertSourceListToTargetList` 空集合返回不可变的 `Collections.emptyList()`；`convertSourceToTarget` 用 Guava `TypeToken` 判断 `Map` / `GXBaseData` 子类型，等价于 `isAssignableFrom` 但更慢。

## 变更后

**异常语义**
- `convertSourceToTarget` 增加 `catch (GXBusinessException | GXBeanValidateException e) { throw e; }`，业务/校验异常原样透传；`unwrapInvocationTargetException` 同样透传 `GXBusinessException`，不再丢失业务码与 `data`。
- 转换失败日志改为 `LOG.error(..., e)` 直接带堆栈（原先只在 debug 分支打堆栈）。

**反射**
- 可访问性判断改为 `method.trySetAccessible()`，对静态方法同样有效，不再依赖 `canAccess(Object)`。
- 新增可变参数支持：`getMethodMatchScore` 按"固定参数 + 可变参数分量"打分，`packVarArgs` 在调用前把尾部实参打包为数组；实参不足固定参数时交回 `invoke` 抛原始异常。
- 新增基本类型拓宽匹配（`Byte/Short/Char/Int/Long/Float/Double` 顺序表，`char` 仅可拓宽到 `int` 及以上），同分时用 `isMoreSpecific` 选参数更具体的方法，消除 `getMethods()` 顺序依赖。
- 零实参场景不再走 `ReflectUtil.getMethod` 的"返回第一个同名方法"快捷路径（可能命中带参重载），改由打分逻辑挑选真正的无参方法。
- `METHOD_CACHE` 改为 `ClassValue<ConcurrentMap<MethodCacheKey, Method>>`，按目标类分槽；超 `MAX_METHOD_CACHE_SIZE_PER_CLASS = 512` 只清理当前类的槽位，类卸载时条目自动释放。

**树构建**
- `buildTree` 改为一次遍历按父 id 分组（`LinkedHashMap` 保序），O(n) 反射调用；用 `IdentityHashMap` 记录已挂载节点，重复 id / 环形引用不再无限递归；孤儿节点数量记录 debug 日志；空输入返回可变列表。
- `setChildren` 缺失时仍静默跳过（仅 debug 日志），与原行为一致，已在 javadoc 中写明。

**配置读取**
- 两个 `getEnvironmentValue` 合并为 `resolveEnvironmentValue(key, clazzType, fallbackSupplier, propagateConversionFailure)`，用 `Supplier` 惰性求默认值；对外签名与"有无默认值"的失败语义保持不变。

**其他**
- `convertStrToTarget` 的 map 形态只剥最外层花括号，新增 `splitTopLevel`（识别引号与 `{}`/`[]`/`()` 嵌套）与 `unquote`。
- `generateHmac` / `checkHmac` 抽出 `hmacSha256` 与 `toJson`；`checkHmac` 的 catch 只包住签名计算，比较逻辑移出。
- `convertSourceListToTargetList` 空输入返回 `new ArrayList<>(0)`；`convertUpdateFieldRequestLst` 去掉冗余 List 与 stream，`UPDATE_FIELD_CLASS_CACHE` 增加 256 上限。
- `TypeToken` 替换为 `Map.class.isAssignableFrom` / `GXBaseData.class.isAssignableFrom`，移除 Guava `TypeToken` 依赖。
- `getSystemLoadAverage` 对 `getProcessCpuLoad()` 的负值返回 `-1` 并夹取到 `[0,1]`；`@SuppressWarnings("all")` 收窄为 `"unchecked"`；通配导入改显式导入；类改为 `final`。
- 补齐类级与关键方法 javadoc：配置缺失返回类型默认值（`String` 为空串）、不传 `CopyOptions` 时类型不兼容字段静默跳过、`checkPhone`/`checkTelephone` 返回 `true` 表示不合法、`hiddenPhoneNumber` 对非手机号返回空串。

## 背景 / 现象

对 CR-052 ~ CR-057 的改动做六维评审，发现 2 个 Critical、4 个 Important、6 条清理项。

### Critical 1：`isWideningConversion` 误判包装类型的拓宽

`getParamMatchScore` 先用 `wrapPrimitiveType` 把形参和实参都归一成包装类型再比较 `numericRank`，于是 `setXxx(Long)` + `Integer` 实参被判为可匹配（得分 12）。

但 `Method#invoke` 的拓宽**只对基本类型形参生效**，对包装类型形参不做任何转换。实测确认：

```
m(Long)  + Integer(7)  -> IllegalArgumentException: argument type mismatch
n(long)  + Integer(7)  -> long:7
o(int)   + Integer(7)  -> int:7
```

可达路径：`GXMongoServiceImpl` 的 `reflectCallObjectMethod(entity, "setXxx", dictValue)`，`Dict` 里的值常是 `Integer`，而 setter 形参可能是 `Long`。表现为通用 CRUD 写入时随机抛 `GXBusinessException: Reflection argument mismatch`。

### Critical 2：严格版 `getEnvironmentValue` 对非 Jackson 异常仍静默降级

`objectMapper.readValue` 的内层 `try` 只 `catch (JacksonException)`。自定义反序列化器抛出的 `IllegalArgumentException` / `NullPointerException` / `ClassCastException` 会落到外层 `catch (Exception)`，在 `throwOnConversionFailure = true` 时记一条 `error` 日志后**返回默认值**——与"反序列化失败即抛 `GXConvertException`"的契约矛盾。开关类配置会被悄悄关掉（`false`），生产环境静默错配。

### Important：弱键缓存失效 + 三处文档与实现不符

- `CONVERTER_CACHE` / `CLASS_METADATA_CACHE` 是 `WeakKeyConcurrentMap<Class<?>, ...>`，键本身正确（`Class` 被 ClassLoader 强引用），但**值会反向强引用键**：值 → `ClassMetadata` → `Map<String, Field>` → `Field#getDeclaringClass()`。弱键因此永远等不到回收，弱引用设计毫无收益。CR-057 只核对了键的存活条件，漏掉了这条路径。
- `GXCommonUtils` 类注释与 `convertSourceToTarget` 的 Javadoc 都写"类型不兼容的字段会被**静默跳过**"，只对 Hutool 分支成立（默认 `CopyOptions` 已 `setIgnoreError(true)`）；CGLIB 分支会尝试转换，失败时打 WARN 并置 null。
- `buildTree` 的 "复杂度 O(n)" 只在 id 唯一时成立；id 重复时 k 个同 id 节点各自遍历同一份 m 个子节点列表，退化为 O(k·m)。
- `convertSourceListToTargetList` 用 `Collectors.toList()`，而 `toList()` 的可变性未定义（JDK 实现恰好是 `ArrayList`），与"始终返回可变列表"的承诺不符。

### Important：缓存命中率的措辞错误

CR-053 / CR-057 与 `GXCGLibDataConvert` 的注释都写"缓存几乎永不命中"。核对 Hutool 源码后确认这是错的：`WeakObj.equals` 按 **referent** 比较（`ObjUtil.equals` → `Objects.equals`），`hashCode` 在构造时取 referent 的 hashCode，所以只要键还没被回收，`get(newKey)` 是**能命中**的。

真正的缺陷是**条目寿命不可控**：`ReferenceConcurrentMap` 每次操作都先 `purgeStale()`，键一旦不可达，下一次 GC 就把条目清掉。缓存退化为"GC 之间有效、GC 之后全丢"，命中率取决于 GC 频率，反复执行 `BeanCopier.create` 持续推高 metaspace。

## 变更前 → 变更后

### 1. 反射调用增加实参对齐

```java
// 变更前：直接 invoke，包装类型形参收到不匹配实参时抛 IllegalArgumentException
final Object[] invokeParams = method.isVarArgs()
        ? packVarArgs(resolvedParams, method) : resolvedParams;
return method.invoke(object, invokeParams);

// 变更后：先按形参类型对齐，再打包可变参数
final Object[] coercedParams = coerceArguments(resolvedParams, method);
final Object[] invokeParams = method.isVarArgs()
        ? packVarArgs(coercedParams, method) : coercedParams;
return method.invoke(object, invokeParams);
```

`coerceArguments` 的实现要点：

- 用 `wrapPrimitiveType(declaredType).isInstance(value)` 判断是否已兼容，避免 `int` 形参配 `Integer` 实参时被误判为需要转换；
- 只在确实需要转换时才 `params.clone()`，常规调用零额外分配；
- 可变参数按**元素类型**逐个对齐，且与 `packVarArgs` 共用"调用方直接传数组"的判定，不会就地改写调用方的数组；
- 转换失败抛 `GXBusinessException`，消息带上方法、参数下标、声明类型与实际类型（原先只有一句 `Reflection argument mismatch`）。

未采用"只给 `isWideningConversion` 加 `declaredType.isPrimitive()` 判断"的最小改法：那样 `setXxx(Long)` + `Integer` 会变成"方法匹配不到 → 静默返回 null"，比报错更难排查。

### 2. 严格版配置读取

```java
// 变更前
} catch (JacksonException exception) {
    return handleConversionFailure(key, clazzType, exception, fallbackSupplier, throwOnConversionFailure);
}

// 变更后：该 try 只包住 readValue 一句，Exception 就等于"反序列化失败"本身
} catch (Exception exception) {
    return handleConversionFailure(key, clazzType, exception, fallbackSupplier, throwOnConversionFailure);
}
```

外层 `catch (Exception)` 继续只兜"环境不可用 / 占位符无法解析"，并在注释里写明 `throwOnConversionFailure` 在该分支只影响日志级别、不会抛异常。宽松版该分支的日志从 `debug` 提到 `warn`（生产默认级别下可见）。

### 3. 两个弱键缓存改为 ClassValue

```java
private static final ClassValue<GXCGLibDataConvert> CONVERTER_CACHE = new ClassValue<>() {
    @Override
    protected GXCGLibDataConvert computeValue(Class<?> type) {
        return new GXCGLibDataConvert(type);
    }
};

private static final ClassValue<ClassMetadata> CLASS_METADATA_CACHE = new ClassValue<>() {
    @Override
    protected ClassMetadata computeValue(Class<?> type) {
        return buildClassMetadata(type);
    }
};
```

与 `BEAN_COPIER_CACHE` 同构，`WeakKeyConcurrentMap` 导入随之删除。顺带把 `buildClassMetadata` 失败时的 WARN 补上堆栈——返回 `EMPTY` 后该类型所有转换都会"字段全空"，只留一行 message 无法定位根因。

### 4. 文档与清理

- `GXCommonUtils` 类注释与 `convertSourceToTarget` 的 Javadoc 改为分述两条分支；
- `buildTree` 的复杂度限定为"id 唯一时 O(n)"；
- `Collectors.toList()` → `Collectors.toCollection(ArrayList::new)`；
- `RANK_*` 常量移到类顶部并注明"必须与 JLS 5.1.2 的拓宽顺序一致"；
- `lookupMethod` 两处逐字重复的同分比较抽成 `pickBetter(MethodMatch, ...)`，`MethodMatch` 为私有 record；
- `propagateConversionFailure` → `throwOnConversionFailure`；
- 删除 `GXCglibUtils` 未使用的 `@Slf4j`；
- `GXBeanCopierCache.get(...)` 的 Javadoc 补上"converter 实例本身不被缓存，`copy` 时必须再传一次"。

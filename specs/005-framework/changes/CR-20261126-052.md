## 背景 / 现象

评审 `util/cglib/GXCglibUtils.java` 发现三类问题：

1. `fillBean` 用原始 key 操作 `BeanMap`。`BeanMap` 的 `keySet`/`containsKey`/`put` 全部按属性名字符串索引，只有 `getPropertyType` 做了 `String.valueOf`，非 String 键会整批静默跳过；同时 `BeanMap` 的 key 集合由 getter 推导，只读属性（无 setter）会通过 `containsKey` 但在 `put` 抛 `IllegalArgumentException`，导致整个 `toBean` 失败。
2. `copyList` 语义不一致：supplier 返回 `null` 时静默丢元素，而 `copyList(Class)` 分支在同类情况下抛异常；空集合返回 `Collections.emptyList()`，与其它分支返回可变 `ArrayList` 不一致，调用方 `add` 会抛 `UnsupportedOperationException`；实例化失败逻辑在两处重复。
3. 公共 API 缺 Javadoc，调用方无法从签名判断「Map 作为 source 不会拷贝任何字段」「不传 converter 时类型不兼容字段被静默跳过」「返回列表可变性」「`toMap` 是实时视图」。

## 变更前

- `fillBean(Map, T)` 与 `toBean(Map, Class)` 使用 raw `Map`，键未归一化，`beanMap.put(rawKey, value)` 直接抛出只读属性异常。
- `copyList` 空集合返回 `Collections.emptyList()`；supplier 返回 `null` 时 `continue` 静默跳过。
- 实例化失败逻辑在 `copy` 与 `copyList(Class, ...)` 中重复两处，均抛裸 `RuntimeException`。
- 类与全部公共方法无 Javadoc。

## 变更后

- `fillBean(Map<?, ?>, T)`：遍历 `entrySet()`，键统一 `String.valueOf` 归一化后用于 `containsKey` / `getPropertyType` / `put`；只读属性写入失败降级为 debug 日志跳过，不再中断填充。
- `toBean(Map<?, ?>, Class)` 复用 `newInstance` 辅助方法。
- `copyList` 空集合返回 `new ArrayList<>(0)`；supplier 返回 `null` 抛 `IllegalStateException`（与 `copyList(Class)` 的 fail-fast 语义对齐）。
- 抽出 `private static <T> T newInstance(Class<T>)`，消除重复实例化逻辑。
- 补齐类级与全部公共方法 Javadoc，明确 Map 源限制、类型不兼容静默跳过、null 元素跳过、回调时机、返回列表可变性、`toMap` 实时视图语义。
- 移除 `fillBean` / `toBean` 的 `@SuppressWarnings("rawtypes")`。

## 验收标准

- [x] 非 String 键（`StringBuilder("name")`）可正确写入同名属性
- [x] 只读属性（仅 getter）不抛异常，其余属性正常填充
- [x] `copyList` supplier 返回 `null` 抛 `IllegalStateException`
- [x] 空集合返回的列表可 `add`
- [x] `mvn -pl leaf-base-framework -o test` 全绿（560 用例，0 失败 0 错误）

## 遗留

- F-16（`GXBeanCopierCache` 弱引用 String 键导致缓存实际失效）未在本 CR 处理，需单独建 CR 改为 `ClassValue` 方案 —— 已由 CR-20261126-053 处理。
- **勘误（CR-20261126-056）**：本 CR 对 `fillBean` 的前提判断有误。实测（Spring cglib 7.0.10）只读属性（仅 getter）在 `BeanMap.put` 上是**空操作、不抛异常**，`IllegalArgumentException` 实际来自 setter 内部的校验拒绝。因此本 CR 新增的 `catch (IllegalArgumentException)` 会吞掉真实的写入失败，已在 CR-20261126-056 中撤销；`fillBeanSkipsReadOnlyPropertyInsteadOfFailing` 也因前提不成立而是空断言。

## 背景 / 现象

## 变更前

1. `packVarArgs` 无条件把尾部实参打包为数组。当调用方**已经传入数组**（`m(String...)` 收到 `String[]`）时，`ReflectUtil.getMethod` 会精确命中 `m(String[])`，随后该数组被当成"单个 vararg 元素"再包一层 → `IllegalArgumentException: array element type mismatch`（实测）。`Object...` 形态不抛异常，而是把 N 个元素静默变成 1 个元素。
2. `fillBean` 用 `catch (IllegalArgumentException)` 跳过"只读属性"。实测（Spring cglib 7.0.10）只读属性在 `BeanMap.put` 上是空操作**不抛异常**，`IllegalArgumentException` 实际来自 setter 内部校验 → 校验失败被静默吞掉，bean 保持旧值，调用方以为成功。CR-20261126-052 的前提判断不成立。
3. `getEnvironmentValue(key, clazzType)` 的 javadoc 承诺"无法反序列化时抛 `GXConvertException`"，但 `getProperty(key, Integer.class)` 的转换异常被降为 debug，简单类型分支直接返回 `0`/`false`；且当天把外层 `LOG.error` 降成了 `LOG.debug`，可观测性进一步下降。
4. `copyList` 每个元素都 `new CopierCacheKey` 并做一次 `HashMap` 查找，单类型集合（主流场景）出现退化。
5. `MethodCacheKey` 直接持有调用方传入的 `Class<?>[]`，作为缓存键后若被修改会破坏 `hashCode`，条目永久不可达。
6. 文档错误三处：`convertSourceToTarget` 写成"目标是 `GXBaseData` 子类走 CGLIB"（实际判据在 source）；`convertStrToTarget` 举例 `{name=a,b}` → `name="a,b"`（实际 `b` 被丢弃，需加引号）；`leaf-base-rabbitmq/pom.xml` 写"Spring Boot 4.2 起"（实测 3.4.5 的 starter 仍依赖 `spring-rabbit`，4.1.2 已只依赖 `spring-boot-amqp`，拆分发生在 4.0）。

## 变更后

**行为修复**
- `packVarArgs`：当 `params.length == fixedCount + 1` 且 `varArgsType.isInstance(params[fixedCount])` 时原样透传，符合 Java 可变参数语义。
- `fillBean`：删除 `catch (IllegalArgumentException)`，只读属性本就是空操作，写入失败必须向上传播。
- `resolveEnvironmentValue`：记录直接转换异常，简单类型且属性确实存在时统一走 `handleConversionFailure` —— 严格重载抛 `GXConvertException`、宽松重载 `warn` 后回退；严格重载的通用失败日志恢复 `error` 级别。
- `copyList`：恢复 `lastSourceClass/lastTargetClass/lastBeanCopier` 三变量零分配快路径，删除局部 `HashMap` 与 `CopierCacheKey` record。
- `MethodCacheKey`：紧凑构造器拷贝参数数组，`paramTypes()` 返回克隆。

**文档校正**
- `convertSourceToTarget` 拷贝策略描述改为"source 是 `GXBaseData` 子类且 target 不是 `Map`"。
- `convertStrToTarget` 改为说明"按顶层逗号切分，值含逗号需加引号"。
- `leaf-base-rabbitmq/pom.xml` 版本描述改为 4.0 起，并注明 3.4.x 仍带 `spring-rabbit`。
- `GXBeanCopierCache` 类注释删除"不会造成 ClassLoader 泄漏"的绝对化表述，改为"随源类型卸载释放，但槽内强引用目标类型"。

**清理**
- `isWideningConversion` 删除恒为 false 的 `declaredWrapper == Character.class` 分支，并修正 `char → int/long/float/double` 的判定顺序（原实现因 `actualRank < 0` 提前返回，该分支不可达）。
- 删除 `convertSourceToTarget` 中恒为 true 的 `isNotEmpty(resolvedMethodName)` 判断、`attachChildren` 中被 `visited` 覆盖的 `candidate == parent` 判断。
- `convertStrToTarget` 的解析失败日志由 `error` 降为 `warn`，原始值只在 `debug` 输出（可能含连接串/口令）。
- `getSystemLoadAverage`：`getProcessCpuLoad()` 返回 `NaN` 视为不可用；`processors <= 0` 返回 `-1` 而不是未归一化的值。

**测试**
- 新增 `shouldPassArrayArgumentThroughToVarArgsMethod`（`int[]` / `String[]` 直接透传）、`shouldPropagateBusinessExceptionFromVerifyHook`（业务码 400 保留）、`fillBeanPropagatesSetterValidationFailure`（setter 拒绝必须抛出），新增内部类 `BusinessRejectingBean`、`ValidatingBean`、`ReflectionTarget#join`。

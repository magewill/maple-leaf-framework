# CR-20261127-055：leaf-base-rabbitmq 迁移到 AMQP 1.0 协议

- 类型：`task`
- 状态：`applied`
- 影响：`leaf-base-rabbitmq`（全部生产与测试代码、`pom.xml`、`AGENTS.md`）；`docs/leaf-base-rabbitmq开发手册.md`；跨模块：`leaf-base-data-sync` 的 RabbitMQ 链路（见「跨模块影响」）
- 日期：2026-11-27
- 关联命令：manual
- 原始记录位置：Session 2026-11-27

## 背景 / 现象

`leaf-base-rabbitmq` 原实现完全基于经典 AMQP 0-9-1 API（`RabbitTemplate` / `RabbitAdmin` /
`CachingConnectionFactory` / `@RabbitListener`）。Spring Boot 4.2 起官方以 AMQP 1.0 为默认
AMQP 支持（`spring-boot-amqp` + `spring-amqp-client` + Qpid ProtonJ2），经典协议拆到
`spring-boot-rabbitmq`。需求是将本模块切换到 AMQP 1.0，并用真实 RabbitMQ（4.4.1）验证。

协议差异带来的硬约束（实测确认）：

1. RabbitMQ 4.x 只接受 AMQP 1.0 v2 地址：发布 `/exchanges/<exchange>/<routing-key>` 或
   `/queues/<queue>`，消费 `/queues/<queue>`；裸队列名会以 `amqp_address_v1_not_permitted` 拒绝。
2. AMQP 1.0 没有 `queue.declare` / `exchange.declare` / `queue.bind`，拓扑必须由客户端通过
   RabbitMQ Management HTTP API 或其他通道创建。
3. 没有 publisher confirm 帧：`accepted` / `rejected` / `released` outcome 取代
   `basic.ack` / `basic.nack` / `basic.return`。
4. 连接 vhost 通过 open 帧的 hostname 传递，Spring Boot 的 `AmqpProperties` 未暴露该字段，
   不显式设置会落到错误的 vhost。
5. RabbitMQ 4.x 默认禁止"非持久化 + 非排他"队列（`transient_nonexcl_queues` 弃用特性）。

## 变更前

- 依赖：`spring-boot-starter-amqp`（排除 `spring-boot-amqp`）+ `spring-boot-rabbitmq`（经典协议）。
- 装配：`RabbitTemplate` / `RabbitAdmin` / `AsyncRabbitTemplate` / `RabbitMessagingTemplate` /
  `ThreadPoolTaskScheduler`，`@EnableRabbit`。
- 发送：`rabbitTemplate.convertAndSend(exchange, routingKey, message, correlationData)`，
  确认/退回/恢复通过 `RabbitTemplate` 回调；`CorrelationData` 为经典类型。
- 拓扑：`RabbitAdmin.declareQueue/declareExchange/declareBinding/purgeQueue/deleteQueue`。
- 消费：`@RabbitListener(queues = ...)`，异常语义依赖容器 `defaultRequeueRejected` 与
  `AmqpRejectAndDontRequeueException`。
- 配置：`GXRabbitMQProperties extends RabbitProperties`，含 `connectionLimit` /
  `channelCacheSize` / `cacheMode` / `channelCheckoutTimeout`（经典连接工厂概念）。

## 变更后

### 依赖与装配

- 依赖改为 `spring-boot-starter-amqp`（AMQP 1.0：`spring-boot-amqp` + `spring-amqp-client` +
  `protonj2-client` + Netty），移除 `spring-boot-rabbitmq` 与 `spring-rabbit-test`。
- `GXRabbitMQConfig` 改为 `@EnableAmqp`，提供：
  - `AmqpConnectionDetails`：`spring.amqp.*` 显式配置优先，回退 `spring.rabbitmq.*`；
  - `ConnectionOptionsCustomizer`：补 vhost（`spring.amqp.virtual-host` →
    `spring.rabbitmq.virtual-host` → `/`）与重连/请求超时；
  - `JacksonJsonMessageConverter`（保留 `DefaultClassMapper` 受信包与 `__TypeId__` 契约）；
  - `GXAmqpMessagePublisher`（发送 + 结算）；
  - `GXAmqpManagementClient`（拓扑管理，可通过 `management.enabled=false` 关闭）；
  - 覆盖默认 `amqpListenerContainerFactory`：`autoAccept=false`，由监听器显式结算。
- 移除 `RabbitTemplate` / `RabbitAdmin` / `AsyncRabbitTemplate` / `RabbitMessagingTemplate` /
  `rabbitTaskScheduler` Bean 与 `maple.framework.rabbitmq.scheduler.expose` 配置键。

### 发送与回调

- 地址由 `GXAmqpAddress` 按 RFC 3986 编码：交换机为空 → `/queues/<routingKey>`，否则
  `/exchanges/<exchange>/<routingKey>`。
- `GXAmqpMessagePublisher` 持有匿名 sender，发送后等待结算，把 `DeliveryState` 映射为
  `GXSendOutcome`（`ACCEPTED` / `REJECTED` / `RELEASED` / `MODIFIED` / `UNKNOWN`）。
- `GXConfirmCallback` 改为 `confirm(GXCorrelationData, boolean ack, String cause)`；
  `GXReturnsCallback` 改为 `returnedMessage(GXReturnedMessage)`（不可路由 = `released`）；
  `GXRecoveryCallback` 在结算失败时触发。
- 新增 `GXCorrelationData`（id + payload + 可等待的结算 Future）替代经典 `CorrelationData`。
- 新增 `sendNormalMessageAwait(dto, timeout)`：同步等待结算，返回是否 accepted。

### 拓扑

- `GXSendRabbitMQService` 方法签名保持不变，实现改为调用 `GXAmqpManagementClient`
  （PUT/DELETE `/api/queues|exchanges|bindings`，Basic Auth，JDK `HttpClient`）。
- `createQueue(..., exclusive=true)` 直接抛 `GXBusinessException`：管理 API 无法创建排他队列。
- `createTemporaryQueue` 语义调整为 `durable=true, exclusive=false, autoDelete=true`，
  原因是 RabbitMQ 4.x 默认拒绝非持久化非排他队列。
- 管理 API 未启用时，拓扑方法抛带明确提示的 `GXRabbitMQOperationException`。

### 消费

- `GXDefaultRabbitMQQueueListenerImpl` 改为 `@AmqpListener(addresses = "/queues/<queue>")`，
  方法签名 `onMessage(Message, AmqpAcknowledgment)`，显式结算：成功 `ACCEPT`、
  `AmqpRejectAndDontRequeueException` → `REJECT`、其他异常 → `REQUEUE`。
- 移除 `@Lazy`：懒加载 Bean 不会注册 `@AmqpListener` 端点（历史缺陷）。

### 配置

- `GXRabbitMQProperties` 不再继承 `RabbitProperties`，改为独立 POJO，前缀仍为
  `spring.rabbitmq`：`host` / `port` / `username` / `password` / `virtual-host` /
  `default-queue-name` / `confirm-timeout` / `management.*`。
- 新增 `maple.framework.rabbitmq.management.*`：`enabled` / `url` / `username` / `password` /
  `virtual-host`。

## 评审修复（2026-11-27，/speckit.review.run）

1. 写出阶段失败时结算 Future 永不完成 → `dispatch`/`sendNormalMessageAwait` 在 `AmqpException` 分支补
   `dispatchOutcome`，保证 `GXCorrelationData.settlement()` 与 confirm/recovery 回调都有终态。
2. `UNKNOWN`/`MODIFIED` 结算结果此前被记为 `rejected` → 改为独立的 "settlement unknown" 分支并触发
   `GXRecoveryCallback`（与 `GXRecoveryCallback` 的 Javadoc 一致）。
3. `sendNormalMessageAwait` 的同步写出失败此前以 `AmqpException` 逃逸，且 `TimeoutException` 分支不可达 →
   统一包装为 `GXRabbitMQOperationException`，删除死分支。
4. `GXAmqpManagementClient#extractReason` 先截断后解析，长响应体导致 RabbitMQ 的 `reason` 丢失 →
   先解析完整响应再截断日志。
5. 管理 API 路径片段改用 RFC 3986 编码（`URLEncoder` 会把空格编码为 `+`）。
6. 发布器补 `closed` 标志：关闭后拒绝新发送、不再重建 sender；结算跟踪被拒绝时以 `UNKNOWN` 上报，
   避免"已写出却报失败"引发重复投递。
7. 监听器结算调用移出 `try`：结算失败不再被当作业务失败二次 `REQUEUE`。
8. `GXAmqpAddress.forQueue` 对空白队列名抛 `GXBusinessException`；新增 `GXAmqpAddressTest`、
   `GXAmqpListenerErrorHandlerTest` 与 3 个结算/包装用例（150 用例）。
9. 文档校正：`createTemporaryQueue` 语义、`RABBITMQ_LISTENER_FAILED` 关键字、
   `spring.amqp.listener.initial-credits`、用例数，以及 `contracts/{listener,send,queue-declaration}-contract.md`。
10. **配置前缀错配**：`confirm-timeout` 与 `management.*` 原先放在 `@ConfigurationProperties(prefix="spring.rabbitmq")`
    的绑定类里，导致文档里的 `maple.framework.rabbitmq.*` 永远不生效（管理 API 地址/凭据、结算超时全部被忽略）。
    已移出绑定类：`confirm-timeout` 改 `@Value("${maple.framework.rabbitmq.confirm-timeout:5000}")`，
    `management.*` 改由 `Environment` 读取。
11. 管理 API 凭据回退链补齐 `spring.amqp.username/password`（此前只回退 `spring.rabbitmq.*`，纯 `spring.amqp` 配置下会 401）。
12. **历史 `spring.rabbitmq.addresses` 被静默丢弃**（仓库 `config/*/rabbit.yml` 全部使用该写法，迁移后会回落 localhost）：
    `GXRabbitMQProperties` 新增 `addresses`，取第一个 `host:port` 作为端点，优先于 `host/port`。
13. 管理 API 失败不再双重记录（客户端降为 debug，服务层单点 error）；`URI.create`/JSON 序列化/绑定列表解析
    统一映射为 `GXAmqpManagementException`，不再让 `IllegalArgumentException` 裸冒泡。
14. `sendNormalMessageAwait` 校验 `timeout`（null/0/负数 → `GXBusinessException`），并给 `.get()` 加上界
    （`timeout + 1s`），超时统一包装为 `GXRabbitMQOperationException`。
15. `sendRawMessage` 不再强制写 `__TypeId__=Dict`（Canal 数组载荷重投会因此转换失败并被首次重试即拒入死信）。
    另修正 `GXCanalConfig` 的 credits 默认值（250 → 100，与 Boot `spring.amqp.listener.initial-credits` 一致）。

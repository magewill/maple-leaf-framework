# CR-20261126-054：适配 Spring Boot 4.2 的 AMQP 模块拆分，恢复 leaf-base-rabbitmq 编译

- 类型：`bugfix`
- 状态：`applied`
- 影响：无 `spec.md` 需求变更；`leaf-base-rabbitmq/pom.xml`；`properties/GXRabbitMQProperties.java`；`config/GXRabbitMQConfig.java`
- 日期：2026-11-26
- 关联命令：`manual`（全仓库编译验证时发现的既有构建失败）

## 背景 / 现象

全仓库 `mvn compile` 时 `leaf-base-rabbitmq` 编译失败，`leaf-base-data-sync` 因其依赖连带失败。两类错误：

1. `org.springframework.amqp.rabbit.*` 全部找不到（`RabbitTemplate`、`CachingConnectionFactory`、`RabbitAdmin`、`ConnectionFactory` 等 8 处）。
2. `org.springframework.boot.amqp.autoconfigure.RabbitProperties` 找不到。

根因是 Spring Boot 4.2 对 AMQP 支持做了模块拆分：

- `spring-boot-starter-amqp` 现在只引入 `spring-boot-amqp` → `spring-amqp-client`，即新的 AMQP 1.0 客户端（`org.springframework.amqp.client.*`），**不再带** AMQP 0-9-1 的 `spring-rabbit`。
- 经典 RabbitMQ 支持（`RabbitAutoConfiguration`、`RabbitProperties`）整体迁移到独立模块 `org.springframework.boot:spring-boot-rabbitmq`，包名由 `org.springframework.boot.amqp.autoconfigure` 变为 `org.springframework.boot.rabbitmq.autoconfigure`。

`spring-rabbit` 在本模块中此前仅通过 `spring-rabbit-test`（test scope）传递进来，编译期不可见；`RabbitProperties` 则完全不存在。

## 变更前

- `pom.xml` 仅声明 `spring-boot-starter-amqp`，未声明 `spring-boot-rabbitmq`。
- `GXRabbitMQProperties` 与 `GXRabbitMQConfig` 导入 `org.springframework.boot.amqp.autoconfigure.RabbitProperties`。
- 模块无自定义 `ConnectionFactory` Bean，依赖 Boot 自动配置提供。

## 变更后

- `pom.xml`：
  - `spring-boot-starter-amqp` 增加 `spring-boot-amqp` 排除（保留 `spring-boot-starter` 与既有 `snakeyaml` / `okio-jvm` 排除），避免同时激活新客户端自动配置；
  - 新增 `org.springframework.boot:spring-boot-rabbitmq`（传递引入 `spring-rabbit`、`spring-amqp`、`com.rabbitmq:amqp-client`，并提供 `RabbitAutoConfiguration`）。
- `GXRabbitMQProperties` / `GXRabbitMQConfig` 的 `RabbitProperties` 导入改为 `org.springframework.boot.rabbitmq.autoconfigure.RabbitProperties`。
- 属性类继承关系与 `RabbitProperties.Template` 用法不变（4.2 中 `getMandatory` / `getReceiveTimeout` / `getReplyTimeout` / `getExchange` / `getRoutingKey` / `getDefaultReceiveQueue` / `isObservationEnabled` 签名一致）。
- `GXQueueDeclarationConcurrencyTest` 的并发夹具改为确定性：`awaitAll` 从 `newCachedThreadPool()` 改为按任务数创建的固定线程池，并加 `ready` 闩等待全部线程就位后再统一放行（原实现中 cached 池懒创建线程，高负载下后创建的线程会在首个声明已完成并移除 in-flight 键之后才到达，导致重复声明）；mock 内的等待时间 100ms / 50ms 同步调至 200ms / 100ms。

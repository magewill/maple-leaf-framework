# CR-20261125-038：014 RpcContext attachment 残留彻底修复（拟议）

- 类型：`bugfix`
- 状态：`proposed`
- 影响：`spec.md#FR-018`；`tasks.md#T066`
- 日期：2026-11-25
- 关联命令：`manual`

## 背景 / 现象

`T066` 复测确认：真实链调用结束后 Dubbo `ContextFilter` 会清理 client attachment，但 Consumer 侧写入的 `getServerAttachment()` 会保留上一次 TraceId。长驻线程连续 RPC 时可能复用旧 TraceId，导致日志与上下文串用。

当前处置为“登记边界 + 加固用例”：

- 边界登记在 `leaf-base-dubbo-nacos/AGENTS.md` §3.2、`contracts/dubbo-trace-context-contract.md` §1、开发手册 §5。
- 新增 `GXDubboFilterChainEndToEndTest#documentsThreadContextBoundaryBetweenSameThreadCalls` 锁定现状。
- 生产代码未改动；彻底修复需变更 P-OK-01 基线，属破坏性变更。

## 变更前

- Consumer 侧 `getServerAttachment()` 的 TraceId 残留被登记为已知边界，未修复。
- 长驻线程连续 RPC 存在 TraceId 串用风险。

## 变更后（拟议，尚未实施）

- 明确 `getServerAttachment()` 的归属与清理责任：由框架在调用边界恢复/清理，或收敛为单一 attachment 来源。
- 保持 `resolveTraceId` 既有优先级链与 P-OK-01 的 MDC 恢复语义；如必须变更锁定断言，需单独评审并登记兼容性影响。
- 补“同线程连续两次调用各自使用当前 MDC TraceId”的回归用例，并做旧实现失败验证。

## 验收标准

- [ ] 同线程连续两次 RPC 不串用上一次 TraceId。
- [ ] P-OK-01 的 MDC 恢复语义与 `resolveTraceId` 优先级链不变，或变更已单独评审。
- [ ] 既有锁定用例不被静默删除/改写。
- [ ] `AGENTS.md`、契约与开发手册同步更新。
- [ ] `changes/INDEX.md` 状态从 `proposed` 推进到 `in-progress` / `applied`。

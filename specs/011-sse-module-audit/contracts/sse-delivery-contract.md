# Contract: SSE 投递语义（顺序 / 重试 / 丢弃 / 关闭）

**Feature**: `011-sse-module-audit` | **Consumers**: 调用方与前端 SSE 客户端

## 1. 保序契约

| 场景 | 保序 | 依据 / 机制 |
| --- | --- | --- |
| 单客户端连续发送（全部成功） | **是** | 同步直发，调用线程顺序即写入顺序（R-03 写锁串行） |
| 单客户端首投失败 + 重试 | **是** | 失败消息进入该 client 的有序队列并作为队首；后续消息入队尾，由唯一 drain 任务串行投递（D-03） |
| 单客户端拆分发送 | **是** | 分片按生成顺序逐条投递；分片共享 `msgId`，注释行带 `chunk=<i>/<n>` |
| 广播到多个客户端 | **客户端之间无序，单客户端内保序** | 每客户端独立同步直发/独立队列 |
| 多线程并发向同一客户端发送 | **按调用实际执行顺序，不承诺跨线程先后** | 写锁保证帧完整；若需严格顺序由调用方串行化 |

## 2. 重试契约

| 触发 | 行为 | 次数 | 退避 | 终止 |
| --- | --- | --- | --- | --- |
| `IOException`（网络/容器写失败） | 该消息留在队首重试 | 最多 3 次（默认不变） | 100 / 200 / 400 ms | 3 次仍失败 → 丢弃消息（`drops++`、`failures++`）→ 关闭连接（`complete()` + 条件删除） |
| `IllegalStateException`（连接已 `complete`） | **不重试**，立即丢弃该消息（`drops++`），DEBUG 记录 | 0 | — | 由容器/调用方的关闭路径清理缓存 |
| `RuntimeException` 其它 | 不重试，丢弃 + WARN（含异常类型） | 0 | — | 不关闭连接（可能仍可用） |
| 缓存中已无该 clientId | 不重试，丢弃（DEBUG） | 0 | — | — |
| 服务已销毁 | 不重试，静默丢弃（DEBUG） | 0 | — | — |

**关键约束**

1. 重试**不得**在调用线程内退避（避免广播阻塞）；一律经由该 client 的队列在共享虚拟线程执行器上执行。
2. 同一 client 同时只能有一个 drain 任务；跨 client 并行。
3. 重试不改变消息的 `msgId` / 注释 / `eventName` / `retry`（重发同一条消息，客户端可据 `msgId` 去重）。
4. 重试耗尽必须"丢弃 + 关闭连接"，**不得**只从缓存移除（F-01）。

## 3. 丢弃契约

| 丢弃原因 | 计数 | 日志级别 | 是否关闭连接 |
| --- | --- | --- | --- |
| 负载为空（`data == null`） | `drops` | WARN | 否 |
| 目标不存在 / `clientId` 空白 | 不计（调用方输入问题） | WARN | 否 |
| 消息为空白（`sendMessageToOneClient`/`sendMessageToAllClient`） | 不计 | WARN | 否 |
| 连接已结束（`IllegalStateException`） | `drops` | DEBUG | 否（容器已结束） |
| 队列超限（> 256） | `drops`（按丢弃条数累加） | WARN | 否（丢弃队首最旧消息，保留最新消息） |
| 重试耗尽 | `drops` + `failures` | ERROR（1 条） | 是 |
| 服务已销毁 | `drops` | DEBUG | 否 |

## 4. 关闭契约

| 入口 | 发 `event: close` | `complete()` | 条件删除 | 幂等 |
| --- | --- | --- | --- | --- |
| `closeConnect(clientId)` | 是（发送失败则跳过） | 是（`finally`） | 是 | 是 |
| 心跳失败 / `sendHeartbeat` 失败 | 否 | 是 | 是 | 是 |
| 重试耗尽 | 否 | 是 | 是 | 是 |
| `destroy()` | 是（逐连接，尽力） | 是 | 是 | 是 |
| 容器 `onCompletion`/`onTimeout`/`onError` | 否（容器已结束） | 不重复调用 | 是 | 是 |
| 同 clientId 被新连接替换 | 否 | 是（对旧 emitter） | 否（`put` 已替换，旧回调的条件删除为空操作） | 是 |

## 5. 不承诺项（必须在手册中声明）

1. **不承诺投递成功**：无 ACK、无持久化、无重放；`Last-Event-ID` 只承载随机 `msgId`，服务端不提供断点续传。
2. **不承诺心跳保活**：心跳只用于探活与清理，连接上限由绝对超时决定（R-04）。
3. **不承诺服务端关闭后不再重连**：`closeConnect` 后浏览器会按 `retry`（默认 2000ms）自动重连。
4. **不承诺跨实例投递**：模块为单实例设计，分布式广播需外部消息总线。
